# Pre-registration: does Lectern find the papers that matter?

Written 2026-11-18, before any tuning run and before any result of the full dev baseline was read. Changes after this
point go in the deviation log at the end, with the reason.

## System under test
The search stage of Lectern, run through its real code: `searchAll`, `merge` and `gather` (which ranks) from
`server/sources/index.js`, with the queries named by each run (`--queries`), no filters, and a ranked list kept to depth
100. Databases and settings as the owner saves them: OpenAlex, Semantic Scholar and Crossref on, Europe PMC off, the
owner's saved OpenAlex and Semantic Scholar keys (`--use-saved-keys`, read in memory, never stored), no contact email.
The answer reads the top 25 (`maxPapers`) and the wide tools read up to 40, so those are the cut-offs that matter. No
model is called by the benchmark runner. Query plans from the planner are recorded by agent D and replayed from a file.

Every database response goes through one cache (`bench/search/data/cache`, keyed by the request without keys), so a
ranking change is measured on the same database answers and a replay is free (`--offline`).

## Data
Gold papers come from three public sources, each chosen by experts and not by a model. Versions, licences and limits
are in `README.md` and `data/manifest.json`.
- **SYNERGY** (De Bruin et al.), commit `7efde4a`: the studies that the authors of a published systematic review
  included after full-text screening. Reviews with 8 to 80 included records.
- **CLEF eHealth TAR 2017 to 2019** (Kanoulas et al.), commit `dbc13d0`: the studies a Cochrane review included
  (full-text "content" relevance 1), PubMed ids mapped to papers through OpenAlex. Test topics only, 6 to 60 included.
- **LitSearch** (Ajith et al. 2024), revision `9573fb2`: questions about ML and NLP papers with the paper(s) that the
  question is about. Quality 2 only: 20 questions written by paper authors (`manual_*`), 10 generated by GPT-4 from
  citing sentences and then checked by experts (`inline_*`).

113 questions: SYNERGY 47, CLEF 36, LitSearch 30. The questions for SYNERGY and CLEF were written by hand by Claude from
the review titles (`data/synergy-questions.json`, `data/clef-questions.json`; committed), as a student would ask them.
That is a model choice in the question text, though not in the gold. LitSearch questions are the dataset's own.
Disciplines: health 49 (CLEF 36 and SYNERGY 13), social science, business and education 22, computer science 36
(LitSearch 30 and SYNERGY 6), environment and other 6.

**Split**: within each source and discipline the questions are shuffled with seed 20261118 + 1 and dealt alternately to
dev and holdout (`build.js`). Dev 56, holdout 57. The ids are in `data/splits.json`. Dev is for tuning and holdout is
frozen. Gold counts: dev 1,182 papers (SYNERGY 786, CLEF 381, LitSearch 15); holdout 1,298 (869, 414, 15).

**Matching a retrieved paper to a gold paper**: normalised DOI (also arXiv DOIs given as alternatives), else the
OpenAlex work id, else identical normalised title of at least 20 characters. A gold paper counts once, at the best rank
of any paper that matches it.

## Metrics
All are means over questions, with a 95% percentile bootstrap interval (10,000 resamples of questions, seed 20261118).
- **Primary: capped recall@25** = (gold papers in the top 25) divided by min(number of gold papers, 25). The cap keeps a
  question with 60 gold papers from limiting the score: it asks how close the top 25 is to the best a list of 25 could do.
- Secondary, all at the same standing:
  - capped recall@40 (the wide tools), uncapped recall@25 and @40 (divided by all gold papers);
  - nDCG@25 with binary gain;
  - MRR (first gold paper);
  - found anywhere: share of gold papers in the merged pool before the ranking cut. A gap between this and recall@40 is a
    ranking miss; a low value is a database or query miss;
  - gold papers returned by each database and gold papers only that database returned, summed over questions;
  - every metric by discipline and by source.
- Differences between two runs on the same questions: paired bootstrap (B minus A, the same resampled questions for both).

## Decision rule: "improved"
A change counts as an improvement on dev only if all hold, comparing the changed run with the baseline run on the same
questions (`compare.js`):
1. capped recall@25 rises and its paired 95% interval excludes 0;
2. nDCG@25 is not worse with its interval excluding 0 (that is, the interval's upper end is not below 0);
3. no discipline group of at least 10 questions has a capped recall@25 loss whose interval excludes 0.
Rises in secondary metrics are reported but do not by themselves make an improvement. A change that only reduces
found-anywhere or only moves ranking is described that way.

Rules for fairness:
- The baseline is `--queries keywords` on the unchanged search code. Query changes (agent D) are replayed from a plan
  file, so the comparison with the baseline isolates the plan. Ranking changes (agent C) are replayed on the same
  cached responses. Database changes (agent B) fetch new answers once and then also replay from the cache.
- Every labelled run on dev is kept in `results/` and counted in the final report, so the number of variants tried is
  known. Dev intervals do not account for choosing among many variants, which is why the holdout is run once.
- A run with a database error on any question is marked incomplete and left out of comparisons until re-run.

## Holdout
The holdout runs once for the baseline and once for the final configuration, only after the project lead says go.
Its numbers are reported as they are. An improvement is claimed only if the holdout difference has the same sign and
its paired 95% interval excludes 0 on capped recall@25, and nDCG@25 is not significantly worse. If dev says better and
holdout does not confirm, the report says so.

## Budgets and limits on requests
2,000 database requests in total for this agent, within each API's published per-second limits (the runner sends one
request at a time per host with a gap: OpenAlex 0.2 s, Semantic Scholar 1.1 s, Crossref 1.1 s). A team-wide counter
(`data/requests.json`) stops all runs at 750 OpenAlex search calls per UTC day, so that the owner keeps 250. No model
calls. Never any key in a cache key, a result or a log.

## What will be said
Recall numbers with n and intervals, per source, with the limits in `README.md`: the gold papers answer a narrow
question that experts asked of a whole literature, so absolute recall is low by construction (the list is 25 papers and
a systematic review may include 60); only differences between runs on the same questions are the evidence. Nothing
will be described as "finds everything" or "no mistakes".
